## Authoring contract

The full spec handed to each author is at
`scratchpad/NUDA-SPEC.md` (session-local). Its load-bearing points:

- Author `cssInline` (drives the live preview) + an **HTML** code tab only. `reconcile.ts`
  regenerates the CSS tab, so preview and copyable code cannot drift. Ship a
  `javascript` tab only when the pattern truly needs it.
- Every id/class/keyframe carries a **per-batch prefix** (`nuda-<prefix>-<slug>`,
  `_nuda-<prefix><slug>`). All `cssInline` is concatenated into ONE global `<style>`, so a
  collision silently corrupts unrelated components.
- GPU-only motion (`transform`/`opacity`/`filter`/`clip-path`/`background-position`/
  `stroke-dashoffset`). Never animate a layout property; never `transition: all`.
- Every `cssInline` ends with `@media (prefers-reduced-motion: reduce)`. No flashing
  >3×/second.
- **Two audit gotchas that break the build:**
  1. `animation: none !important` needs the space. `animation:none!important` makes
     `registry-audit.ts` read `none!important` as an animation *name* and demand a
     matching `@keyframes`.
  2. No layout property inside `@keyframes` — slide with `translate*()`, fill a bar with
     `scaleX()` + `transform-origin: left`.

## Verification harness

`src/lib/wave-verify.test.ts` (TEMPORARY — delete once wiring is done) auto-discovers
every `*-extra.tsx` batch and audits it *before* it is wired in. Beyond the permanent
`registry-audit.ts` invariants it enforces: exact per-batch count, prefix discipline on
ids and classes, a reduced-motion block per component, no layout props in `@keyframes`,
no `transition: all`, HTML tabs that are real HTML (not JSX), and **id + `@keyframes`
collisions** both across new batches and against the 1022 already-wired components.

Only *authored* batches are asserted, so unfinished work never fails the build.
Run `NUDA_AUDIT_COMPLETE=1 npx vitest run src/lib/wave-verify.test.ts` to also assert the
plan is complete.
